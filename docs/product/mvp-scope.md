# AI 用药伴侣 MVP 介绍

## 一句话定位

AI 用药伴侣是一个面向中老年用药管理场景的移动端 Web Demo。它不替代医生或药师，而是帮助用户把药品包装上的可见信息整理成可确认、可提醒、可记录、可追溯的电子药箱。

## 核心用户旅程

1. 用户登录 Demo。
2. 上传药品包装图。
3. 系统校验图片，并用固定说明文本或 MiniMax 生成结构化药品信息。
4. 用户核对药品名称、规格、用法、警示信息和提醒时间。
5. 用户确认后，药品进入电子药箱。
6. 今日提醒页生成待记录事项。
7. 用户标记已服、稍后、漏服或不适。
8. 问答页基于来源片段回答普通问题。
9. 涉及加减药、停药、胸痛、呼吸困难、严重过敏等高风险问题时直接拒答，并建议联系医生或药师。

## 展示重点

- 有真实页面，不是静态截图。
- 有完整 API 闭环，不是纯前端 mock。
- AI 结果不会自动保存，必须人工确认。
- 高风险问题不交给模型自由发挥。
- MiniMax 不可用时仍能走兜底流程，保证面试演示稳定。
- Docker Compose + Caddy 可以部署到 Debian 13 VPS，并通过 HTTPS 访问。

## 包含范围

- 移动端优先 H5 页面。
- Demo 账号登录。
- JPG/PNG 上传校验和保存。
- 固定说明文本的结构化识别兜底。
- MiniMax OpenAI-compatible 文本结构化和问答接口。
- 人工确认页。
- 电子药箱。
- 今日提醒和服药状态记录。
- 7 天记录摘要。
- 普通问答和高风险拒答。
- PostgreSQL/SQLite 数据模型。
- Docker Compose + Caddy 部署配置。

## 不包含范围

- 真实 OCR 准确率评估。
- 真实药品数据库。
- 医疗诊断。
- 自行调整剂量或疗程建议。
- 家属共享。
- 短信、微信或原生推送提醒。
- 医生后台。
- 真实用户隐私数据处理流程。

## 技术实现摘要

- `FastAPI` 提供页面和 JSON API。
- `Jinja2` 渲染页面模板。
- `Vanilla JS` 负责登录、上传、确认、提醒和问答交互。
- `SQLAlchemy` 管理用户、药品、提醒、记录和问答日志。
- `Pydantic` 约束 AI 输出和接口 payload。
- `MiniMax-M2.7` 负责文本整理和问答，失败时进入本地兜底。
- `Caddy` 通过 `DEMO_DOMAIN` 自动申请 HTTPS 证书并反向代理到 app 容器。

## 最需要验证的产品假设

中老年用户是否愿意在 AI 给出结构化结果后完成一次人工确认。如果确认步骤过重，即使识别准确，也难以形成稳定的电子药箱和提醒管理习惯。
