# AI 用药伴侣产品设计

## 设计目标

本 MVP 是面试演示产品，不追求完整医疗闭环。设计目标是用一个可访问的 Web/H5 Demo 展示完整功能链路：上传药品图片、AI 整理用药信息、人工确认、进入电子药箱、页面提醒、服药状态记录、用药问答和高风险拒答。

## 产品边界

MVP 定位为“用药管理与信息辅助工具”，不是诊断工具、处方工具或换药决策工具。

系统可以整理包装或说明文本中的可见信息，但不能自动决定药名、剂量、频次或疗程。所有进入药箱和提醒的药品信息必须经过用户确认。

问答只能解释当前药品文本、Demo 内置文本和安全规则覆盖的信息。涉及加量、减量、停药、换药、合并用药、胸痛、呼吸困难、严重过敏等问题时，系统拒绝给出医疗建议，并提示咨询医生、药师或急救。MiniMax key 不可用或模型调用失败时，绿色和黄色问题使用当前药品来源片段生成保守兜底回答，红色问题仍直接拒答。

## 页面设计

产品口径为 6 个用户可见页面、7 个页面路由；其中“上传页”和“确认页”是同一条添加药品流程的两个步骤。

| 页面 | 核心内容 | 设计要求 |
| --- | --- | --- |
| 登录页 | 测试账号、隐私提示、进入按钮 | 说明这是 Demo 和健康信息辅助工具，避免让用户误以为是医生系统 |
| 首页 | 拍照添加药品、今日提醒、问一问 | 三个主按钮，适合手机点击，减少导航层级 |
| 上传与确认页 | 图片预览、识别结果、来源片段、编辑字段、确认勾选 | 这是安全核心页，未确认不得保存 |
| 电子药箱页 | 药品卡片、提醒时间、今日状态、问答入口 | 图片和药名帮助老人识别药品 |
| 提醒记录页 | 当前提醒、四个状态按钮、7 天摘要 | 按钮高度不低于 52px，状态颜色和文字同时表达含义 |
| 问答页 | 常见问题、输入框、回答、来源、安全标签 | 默认展示安全边界，红色问题明确拒答 |

## 核心流程

1. 用户登录 Demo。
2. 用户上传药品包装图片。
3. 系统保存图片，尝试 OCR；OCR 不可用或文本太短时使用固定 Demo 药品文本。
4. MiniMax-M2.7 将文本整理成药名、规格、用法原文、提醒频次建议、警示、来源片段和置信度；模型不可用时返回固定 Demo 结构化结果并标记 `fallback_used=true`。
5. 用户在确认页修改字段并勾选确认。
6. 系统保存药品、提醒计划和来源片段。
7. 用户在药箱查看药品。
8. 到 Demo 提醒时间后，用户选择已服、稍后、漏服或不适。
9. 用户围绕药品提问，系统按安全分级回答；红色问题本地拒答，绿色和黄色问题在模型不可用时返回来源片段兜底回答。

## 信息安全与医疗安全

- 不保存真实身份证、病历、医保、地址等信息。
- 上传图片只用于本次 Demo 药品识别和展示。
- 模型失败时不向用户暴露异常栈，直接使用兜底样例并标记结果来自 Demo。
- 药品确认前不生成正式提醒。
- 红色风险问题不调用模型，直接进入拒答模板。
- 所有问答保存安全标签，便于截图展示安全策略。

## 成功标准

- 用户能在手机视图完成登录、上传、确认、药箱、提醒记录和问答闭环。
- 页面看起来是可体验产品，而不是裸接口或表格堆叠。
- MiniMax key 不可用时，Demo 仍能展示完整流程。
- 高风险问答不输出处方、诊断、换药或剂量调整建议。
- 面试材料能直接截图展示用户旅程、系统 Prompt、工作流、接口、部署和 UI。
