# MVP 范围

## 目标

这个 MVP 用于测试题和面试展示，不追求完整医疗系统。它只证明一个中老年用药管理闭环可以被快速体验：

1. Demo 账号登录。
2. 上传药品包装图。
3. 系统生成结构化药品信息。
4. 用户人工确认后保存到电子药箱。
5. 今日提醒页记录服药状态。
6. 问答页基于药品来源片段回答普通问题。
7. 高风险问题直接拒答并建议联系医生或药师。

## 包含范围

- 移动端优先 H5 页面。
- FastAPI 页面和 API 单服务。
- PostgreSQL/SQLite 数据模型。
- MiniMax OpenAI-compatible 文本结构化和问答接口。
- MiniMax 不可用时的固定样例兜底。
- 红色风险问题本地规则拒答。
- Docker Compose + Caddy 部署配置。

## 固定样例兜底说明

当前上传流程会校验并保存用户上传的 JPG/PNG 图片，但测试题 Demo 为了保证可复现，识别输入使用内置药品说明文本。MiniMax key 为空、网络失败或返回格式错误时，都会进入同一套固定样例兜底结果；非真实 JPG/PNG 图片会被上传接口直接拒绝。

这不是完整 OCR 能力。真实产品下一步应接入 OCR 或视觉模型，把图片中的文字作为 `raw_text` 进入同一套结构化和人工确认流程。

## 不包含范围

- 真实药品数据库。
- 医疗诊断。
- 自行加量、减量、停药、换药建议。
- 家属共享。
- 短信、微信或原生推送提醒。
- 医生后台。
- OCR 准确率评估。

## 最需要验证的假设

中老年用户是否愿意在 AI 给出结构化结果后完成一次人工确认。如果确认步骤过重，再准确的识别也难以形成稳定用药管理习惯。
